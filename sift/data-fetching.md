Sift uses RTK Query for data fetching with auto-generated API clients from OpenAPI specs.
All API calls go through generated hooks — never use `fetch`/`axios` directly.

## Generated API

Hooks and types live in `src/gen/api/azimuth_api.ts`, auto-generated by `npm run gen:rtk`.
These are enhanced in `src/api/grpc_api.ts` with cache tags and helper exports.

**Regenerate when the OpenAPI spec changes** (new endpoint, new field):
```bash
npm run gen:rtk
```

## Usage Patterns

**Queries** with conditional fetching (used heavily):
```tsx
const { data, isLoading, error } = grpcApi.useAssetServiceGetAssetQuery(
  { assetId },
  { skip: !assetId }
);
```

**Mutations** with unwrap:
```tsx
const [updateRun, { isLoading }] = grpcApi.useRunServiceUpdateRunMutation();
await updateRun({ v2UpdateRunRequest: { runId, name, updateMask: 'name' } }).unwrap();
```

**Custom hooks** in `src/api/hooks/` compose multiple generated queries with domain logic.

## Cache Invalidation with Tags

RTK Query uses tags for automatic cache management:
- **Query endpoints**: `providesTags` marks what data the query provides
- **Mutation endpoints**: `invalidatesTags` marks which caches to refetch

Tags are configured in `src/api/grpc_api.ts` via `enhanceEndpoints`. When a mutation
succeeds, all queries with matching tags automatically refetch.

## Error Handling

Errors are normalized via `AzimuthError.fromUnknown(error)` from `src/api/AzimuthError.ts`.
This handles `AzimuthError`, standard `Error`, and gRPC error shapes. Error boundaries
(`RootErrorBoundary`) catch component-level render failures.

Error handling is not yet fully standardized — handle errors inline and gracefully for now.
